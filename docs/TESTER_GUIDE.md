# 사용성 시험 참여 안내

findr 사용성 시험에 참여해 주셔서 고맙습니다. 이 안내는 개발자가 아닌 분도 따라 할 수 있게 썼습니다. 한 번에 **30~40분**이면 됩니다.

시험의 목적은 프로그램을 시험하는 것이지 여러분을 시험하는 것이 아닙니다. 막히거나 헷갈리는 순간이 가장 귀한 결과입니다. 그런 순간이 오면 바로 도움을 청하지 말고, 먼저 **무엇을 기대했는지**와 **무엇이 보였는지**를 적어 주세요.

> 개발자용 시험 절차와 측정 도구는 [FIELD_TESTING.md](FIELD_TESTING.md)에 있습니다.

## 0. 시작 전에

| 확인할 것 | 방법 |
|---|---|
| 버전 | [배포 페이지](https://github.com/quantumaikr/findr/releases/latest)의 **0.2.11 이상**을 받으세요. 0.2.10은 새로 설치할 때 의미 검색 모델을 받지 않는 문제가 있습니다 |
| 여유 공간 | 15GB 이상 (구성과 모델 2~12GB, 색인) |
| 인터넷 | 처음 준비할 때만 씁니다. 회사망이라면 `github.com`과 `huggingface.co`에 들어가지는지 미리 확인해 주세요 |
| 전원 | 노트북은 전원을 연결해 주세요. 배터리로 쓸 때는 자동 색인을 미룹니다 |
| PC 정보 | 아래 기록지의 "PC 정보" 칸을 먼저 채워 주세요 |

**Mac:** Apple 칩(M1 이후)만 지원합니다. 메모리 용량은 Apple 메뉴 → 이 Mac에 관하여에서 확인합니다.

**Windows:** 설정 → 개인 정보 및 보안 → Windows 보안 → 앱 및 브라우저 컨트롤에서 '스마트 앱 컨트롤'이 켜져 있는지 확인해 주세요. 켜져 있어도 됩니다. 켜진 상태에서의 결과도 필요합니다.

## 1. 설치 (시간을 재 주세요)

| 운영체제 | 받을 파일 | 설치 |
|---|---|---|
| Windows 10, 11 | `findr_<버전>_x64-setup.exe` | 실행합니다. **"Windows의 PC 보호"** 창이 뜨면 "추가 정보" → "실행" |
| macOS (Apple 칩) | `findr_<버전>_aarch64.dmg` | 열어서 findr를 응용 프로그램 폴더로 끌어 놓습니다. 처음 열 때는 **오른쪽 클릭 → 열기** |

아직 코드 서명 전이라 경고가 나옵니다. 정상입니다. 다만 경고 때문에 멈칫했다면 그것도 기록해 주세요.

macOS에서 "손상되었기 때문에 열 수 없습니다"가 나오면 터미널에서 아래를 한 번 실행합니다.

```bash
xattr -cr /Applications/findr.app
```

### 소스로 설치하기 (GitHub 최신 코드)

진행자가 앱 대신 최신 코드로 시험하자고 하면 이 방법을 씁니다. 배포 전 수정이 바로 들어가 있습니다. git이 필요합니다. Windows에서 없으면 `winget install Git.Git`으로 설치하고, Mac에서는 터미널에서 `git --version`을 치면 설치 안내가 나옵니다.

```powershell
# Windows (PowerShell)
git clone https://github.com/quantumaikr/findr
cd findr
powershell -ExecutionPolicy Bypass -File install.ps1
.\findr doctor
```

```bash
# macOS
git clone https://github.com/quantumaikr/findr && cd findr
bash install.sh
./findr.sh doctor
```

설치 스크립트가 전용 파이썬, 검색 엔진, 모델을 받습니다. 사양에 따라 5~20분 걸리니 시간을 재 주세요. `doctor`가 모두 ✓이면 준비가 끝난 것입니다.

이후 단계는 앱과 같고, 명령만 다릅니다. 아래는 Windows 기준이고, macOS는 `.\findr` 대신 `./findr.sh`를 씁니다.

| 앱에서 | 소스 설치에서 |
|---|---|
| 폴더를 고르고 색인 시작 | `.\findr index` (PC 전체) 또는 `.\findr index D:\자료` |
| 검색 화면 | 다른 창에서 `.\findr serve`를 실행하면 브라우저에 검색 화면이 열립니다. **색인이 끝나기 전에 켜서** 색인 중에도 검색되는지 봐 주세요 |
| 앱 끄고 다시 켜기 | `serve` 창에서 Ctrl+C를 누른 뒤 다시 `.\findr serve` |
| 데이터 폴더 | `doctor` 첫 줄에 나오는 경로. 로그는 그 안의 `logs` |

- Windows 명령 프롬프트(cmd)에서는 `findr` 대신 `findr.cmd`로 실행합니다. 같은 이름의 폴더가 있어 `findr`만으로는 인식되지 않습니다.
- 코드를 새로 받을 때는 `git pull` 뒤에 설치 스크립트를 **다시 실행**하세요. `git pull`만으로는 새 구성 요소가 설치되지 않습니다.
- 소스 설치에는 앱의 첫 화면과 설정 화면이 없습니다. 6번(설정 둘러보기)은 건너뛰세요.

## 2. 처음 실행: 준비

처음 실행하면 PC에 맞는 구성(검색 엔진, 모델)을 받습니다. 사양에 따라 **5~20분** 걸립니다.

- 진행 표시가 지금 무엇을 하는지 알려 주는지
- 기다리는 동안 불안하거나 지루했는지

이 두 가지를 적어 주세요.

## 3. 첫 색인

평소 파일을 두는 폴더를 고르거나 "PC 전체"를 고릅니다. findr는 다음 순서로 점점 똑똑해집니다.

**파일 이름 → 이름의 뜻 → 문서 속 글자 → 내용의 뜻 → 스캔 속 글자**

- **이름으로 검색할 수 있게 되기까지 걸린 시간**을 재 주세요. "검색 시작하기" 버튼이 눌리게 되는 때입니다. 바로 넘어가지 않으면 잠시 뒤 저절로 검색 화면으로 넘어갑니다.
- 색인이 끝나지 않았어도 검색해 보세요. 검색이 되는 것이 정상입니다.
- 검색 화면 위쪽의 진행 표시("살펴보는 중 ○%")를 눌러 단계별 진행을 보고, **"잠시 멈추기"**를 한 번 눌렀다가 **"이어서 하기"**로 다시 이어 보세요. 잊고 두어도 한 시간 뒤에는 저절로 이어집니다.

## 4. 질문 10개

미리 종이에 질문 10개를 적어 두세요. **실제로 찾을 일이 있을 법한 파일**로 정하고, 정답 파일이 무엇인지 알고 있어야 합니다.

| 종류 | 개수 | 예 |
|---|---|---|
| 이름으로 | 3 | "작년 사업계획서", "3분기 매출 보고서" |
| 내용으로 | 3 | "임대료를 비교했던 문서", "채용 일정 논의한 회의록" |
| 막연하게 | 2 | "지난번에 보낸 견적", "그때 그 발표 자료" |
| 말을 바꿔서 | 1 | 파일 이름은 "사무실 이전"인데 "사무실 옮기는 계획"이라고 묻기 |
| 버전 | 1 | "계약서 최종본 말고 그 전 판" |
| **PC에 없는 것** | 1 | 확실히 없는 파일. findr가 없다고 말하는지 봅니다 |

질문마다 아래를 기록합니다.

- 찾는 파일이 **몇 위**였나요? (1위 / 2~3위 / 4~10위 / 없음)
- 답이 나오기까지 체감 시간은요? (바로 / 조금 기다림 / 답답함)
- 결과를 눌러 **파일을 열어 확인**했나요? 열어 보고 나서야 맞는지 알았나요?
- 의외였던 결과가 있었나요?

## 5. 다시 켜 보기

앱을 완전히 껐다가 다시 켜고 바로 한 번 검색합니다. 첫 검색이 바로 나오는지 봐 주세요.

## 6. 설정 둘러보기

- **GPU 없는 PC:** "쉬는 시간에 더 정확한 의미 모델로 바꾸기" 항목의 설명이 이해되는지
- **AI 도구에 연결:** 설명을 읽고 무엇을 하는 기능인지 알겠는지 (실제 연결은 하지 않아도 됩니다)

## 7. 문제가 생기면

화면을 캡처하고, 아래 명령의 출력을 함께 보내 주세요. 명령은 Windows는 명령 프롬프트, Mac은 터미널에서 실행합니다.

```bat
:: Windows (앱)
%LOCALAPPDATA%\findr\runtime\Scripts\python.exe -m findr doctor
:: Windows (소스 설치: 저장소 폴더에서)
findr.cmd doctor
```

```bash
# macOS (앱)
~/.findr/runtime/bin/python -m findr doctor
# macOS (소스 설치: 저장소 폴더에서)
./findr.sh doctor
```

로그는 데이터 폴더 안의 `logs`에 있습니다. 위치는 Windows `%LOCALAPPDATA%\findr\logs`, macOS `~/.findr/logs`입니다. 1.5초 넘게 걸린 질문은 로그에 `FINDR_SLOW` 줄이 남습니다. 이 줄에는 단계별 시간만 들어가고 질문 내용은 들어가지 않습니다.

## 8. 개인정보

- 색인과 검색은 **모두 이 PC 안에서** 이뤄집니다. 파일 내용은 밖으로 나가지 않습니다.
- 기록지와 로그에는 **파일 이름이 들어갈 수 있습니다.** 진행자에게 보내기 전에 실제 파일, 회사, 사람 이름을 "견적서A", "고객사B"처럼 바꿔 주세요.
- 공개 GitHub 이슈에 올릴 때는 특히 주의해 주세요. 공개 저장소에서는 나중에 고쳐도 수정 기록에 남습니다.

## 9. 시험이 끝나면

계속 쓰셔도 됩니다. 쓸수록 쉬는 시간에 보완되며 정확해집니다. 지우려면 아래처럼 하면 색인까지 모두 지워집니다.

- **Windows:** 설정 → 앱 → findr 제거. 그 뒤 `%LOCALAPPDATA%\findr` 폴더가 남아 있으면 지웁니다.
- **macOS:** 응용 프로그램 폴더의 findr를 휴지통으로 옮기고 `~/.findr` 폴더를 지웁니다.
